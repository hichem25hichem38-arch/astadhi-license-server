# خادم تراخيص أستاذي

يمنح كل عميل رمز تفعيل فريدًا مرتبطًا بعدد محدد من الأجهزة. نسخ التطبيق إلى جهاز آخر لا يعمل دون رمز جديد — التذكرة موقعة ومربوطة ببصمة الجهاز وتُتحقق دون إنترنت.

## التشغيل محليًا (للتجربة)

```powershell
$env:ADMIN_PASSWORD = 'كلمة-قوية-جدا'
node server.js
```

افتح `http://localhost:48721` (لوحة الإدارة) بنفس كلمة المرور.

## النشر للإنتاج (مثال Render المجاني)

1. ارفع مجلد `license-server` إلى مستودع Git خاص.
2. أنشئ خدمة Web في Render: أمر التشغيل `node server.js`، وأضف متغير البيئة `ADMIN_PASSWORD` (قيمة قوية) و`PORT` (يضبطها Render تلقائيًا).
3. ستحصل على رابط مثل `https://astadhi-licenses.onrender.com` — ضعه في `SERVER_URL` داخل `license-client.js` في التطبيقين ثم أعد بناءهما.
4. ملف `data/db.json` يحفظ الرموز والأجهزة — فعّل قرصًا دائمًا (Disk) في Render أو انسخه احتياطيًا دوريًا، وانسخ `data/keys.json` (المفاتيح) واحتفظ به في مكان آمن: فقدانه يُبطل كل التذاكر.

## استعمال اللوحة

- **رمز جديد:** اسم العميل + المدة بالأيام (5 للتجربة، 365 للسنة، 36500 للدائم تقريبًا) + عدد الأجهزة (1 غالبًا) ← انسخ الرمز وأرسله للعميل.
- **إلغاء عميل:** زر إلغاء بجانب الرمز — يتوقف تطبيقه عند أول اتصال (الفحص الدوري كل 3 أيام) وفورًا عند إعادة التفعيل.
- **نقل جهاز:** احذف الجهاز القديم من جدول الأجهزة (زر الحذف) ليفسح مكانًا للجديد — أو ارفع عدد الأجهزة.
- **انتهاء المدة:** تُرفض التذاكر تلقائيًا بعد `expiry` حتى دون إنترنت.

## كيف يمنع نسخ التطبيق لجهاز آخر؟

1. بصمة الجهاز: أندرويد `ANDROID_ID` عبر إضافة Device، والحاسوب `machine-id` عبر القناة الأصلية — ثابتة لكل جهاز ومختلفة بين الأجهزة.
2. التذكرة الموقعة تحتوي البصمة؛ أي جهاز آخر يفشل التحقق المحلي فورًا وتظهر شاشة التفعيل.
3. الخادم يرفض تسجيل جهاز جديد بعد بلوغ `maxDevices`.

## ملاحظات تقنية

- التوقيع ECDSA P-256 بصيغة `ieee-p1363` (التي يتوقعها WebCrypto) — لا تغيّرها.
- `LICENSE_REQUIRED = false` افتراضيًا (وضع التجربة الاحتياطي يعمل). لنسخ العملاء المرخّصة ضعه `true` مع `SERVER_URL` الإنتاجي قبل البناء.
- لا تُغيّر `ADMIN_PASSWORD` الافتراضية `change-me` في الإنتاج أبدًا.
